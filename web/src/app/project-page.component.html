Das technische Projekt

Hinter dem Gesicht
steckt Verhalten.

PinkRobin verbindet einen portablen C++-Core mit einem ASP.NET-Core-Backend und einer Angular-Oberfläche. Hier zeige ich, wie aus einer Eingabe Robins Reaktion wird und welche Entscheidungen hinter dem Aufbau stehen.

Robin selbst erleben ↗

01 / Architektur

Drei Teile.
Klare Aufgaben.

  1. 01

    Angular

    Eingabe und Darstellung

    Erfasst Berührungen und die Wetterfrage. Zeigt Robins Gesicht, Outfit und Antworten an.

  2. 02

    ASP.NET Core

    Transport und Dienste

    Verwaltet getrennte Sitzungen, lädt Wetterprognosen und verbindet den Browser über eine C-Schnittstelle mit dem Core.

  3. 03

    C++-Core

    Zustand und Verhalten

    Verarbeitet Nachrichten, hält Wetterwissen und Robins Zustand. Prüft Fähigkeiten und Freigaberegeln für seine Aktionen.

↩ Zustand und typisierte Ausgaben gelangen über das Backend zurück zur Darstellung.

Ein Kern für verschiedene Plattformen

Der Core benötigt weder Browser noch Netzwerkzugriff oder eine eigene Uhr. Adapter liefern Nachrichten, Zeit und unterstützte Fähigkeiten. Das bildet die Grundlage für spätere iPad- und Hardwareversionen.

02 / Ein konkreter Ablauf

„Robin, wie wird
das Wetter?“

Die Wetterfrage zeigt, wie gespeichertes Wissen, Entscheidung und Darstellung zusammenspielen.

  1. Wetterwissen bereitstellen

    Das Backend lädt eine Prognose für die gewählte Schweizer Postleitzahl. Der Core übernimmt die Werte mit Herkunft und zeitlicher Gültigkeit in sein WorldModel.

  2. Die Frage übermitteln

    Der Wetterfrage-Button sendet einen nummerierten Befehl. Das Backend verhindert, dass eine Wiederholung des zuletzt angenommenen Befehls eine zweite Antwort erzeugt.

  3. Eine Antwort erzeugen

    Bei unterstützter Textausgabe erzeugt der Core eine typisierte Antwort: trocken, Regen, stürmische Prognose oder unbekannt. Abgelaufenes Wissen wird nicht verwendet.

  4. Anzeigen und bestätigen

    Angular formuliert den deutschen Text und zeigt ihn acht Sekunden an. Erst die Bestätigung entfernt die Ausgabe aus dem Core-Puffer. Bei einem Bestätigungsfehler wird die Bestätigung erneut versucht.

Zustand ist nicht dasselbe wie eine Ausgabe

Ein Outfit bleibt als Zustand abfragbar. Eine Antwort besitzt dagegen eine eigene Sequenznummer und wartet auf Bestätigung. Wiederholtes Lesen entfernt sie nicht. Der Puffer ist begrenzt und liegt im Arbeitsspeicher; eine dauerhafte Zustellung über Neustarts hinweg ist damit nicht garantiert.

    Adapter melden Textausgabe und Outfit-Darstellung ausdrücklich. Der Core führt nicht unterstützte Aktionen nicht aus.

Qualität gehört zum Verhalten

Automatisierte Tests prüfen unter anderem Zeitgrenzen, Nachrichtenreihenfolge, Puffergrenzen und Session-Trennung. GitHub Actions prüft Core und native Backend-Anbindung auf Windows, Linux und macOS sowie Web-Tests und Angular-Build.
