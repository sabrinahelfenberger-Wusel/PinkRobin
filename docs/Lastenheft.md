Projekt: Pink Robin -> Modularer sozialer Begleitroboter
# Projektphilosophie
Ziel ist es nicht die schnellst mögliche Entwicklung eines fertigen Roboters, sondern der Aufbau einer langfristig wartbaren, Modularen Robotikplattform. Hardware und Software sollen klar von einander getrennt werden. Alle Komponenten sollen austauschbar sein und definierte Schnittstellen besitzen. Standardkomponenten werden bevorzugt, um Wartbarkeit, Reparaturfähigkeit und Kosten zu optimieren.

# 1 EinLeitung
# 1.1 Ziel des Projekts
Entwicklung eines Modular aufgebauten sozialenBegleitroboters, der durch Mimik, Sprache und Bewegung natürlich mit Menschen interagieren kann.

Der Roboter soll lokal schnell reagieren und komplexe Aufgaben über ein externe KI-System lösen können.

Das System soll langfristig erweiterbar sein und als Lernplattform für Embedded-Systeme, Softwareentwicklung, Elektronik, Mechanik und künstliche Intelligenz dienen.
# 2 Projektziele
Der Roboter soll:
- sozial und sympathisch wirken
- modular aufgebaut sein
- wartbar und erweiterbar sein
- überwiegend aus Standardkomponenten bestehen
- möglichst geringe Entwicklungskosten verursachen
- langfristig weiterentwickelt werden können

# 3 Nicht-Ziele
Der Roboter soll nicht:
- ein vollwertiger Haushaltsroboter sein
- Menschen ersetzen
- industrielle Robotik nachbilden
- ausschliesslich cloudbasiert funktionieren

# 4 Systemübersicht
Das Gesamtsystem besteht aus:
- Roboterkopf
- Roboterbauch
- Beinmodul
- Ladestation
- Homestation
- Server
- Webanwendung
- Mobile App

# 5 Anforderungen
# 5.1 Kopf
Der Kopf muss:
- Emotionen darstellen können
- Sprache wiedergeben können
- Sprache aufnehmen können
- Personen erkennen können
- Berührungen erkennen können
- Kopfbewegungen ausführen können
- lokal auf Sprache reagieren können

# 5.2 Bauch
Der Bauch muss:
- Energieversorgung übernehmen
- Akku laden
- Drehbewegung ermöglichen
- Sensoren aufnehmen
- Kommunikation mit den Beinen übernehmen
- Kommunikation mit dem Kopf übernehmen

# 5.3 Beine
Die Beine sollen:
- modular austauschbar sein
- selbstständig angesteuert werden
- über Kontakte verbunden werden (Pogo-Pins)

# 5.4 Server
Der Server soll:
- OAT-Updates bereitstellen
- Roboter verwalten
- Konfiguration speichern
- Livestream bereitstellen
- API bereitstellen

# 5.5 Mobile App
Die Mobile App soll
- Roboter erkennen
- Firmware aktualisieren
- Einstellungen ändern
- Status anzeigen

# 5.6 Weboberfläche
Die Weboberfläche soll:
- Livestream anzeigen
- Roboterstatus anzeigen
- Einstellungen ermöglichen
- Firmware verwalten

# 6 Qualitätsanforderungen
- Modularer Aufbau
- einfache Wartbarkeit
- einfache Erweiterbarkeit
- Hardwareunabhängige Softwarearchitektur
- Wiederverwendbarkeit
- geringe Latenz
- geringer Energieverbrauch

# 7 Randbedingungen
- Standardkomponenten sollen bevorzugt verwendet werden.
- Sonderanfertigungen sollen sich auf Leiterplatten und Gehäuse beschränken.
- Software soll möglichst hardwareunabhängig entwickelt werden.
- Prozessorwechsel sollen mit möglichst geringem Softwareaufwand möglich sein.
